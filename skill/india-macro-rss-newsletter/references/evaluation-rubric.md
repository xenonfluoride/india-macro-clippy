# Newsletter evaluation rubric

Run the evaluator before delivery. It protects the requirements that matter most:

| Area | Pass condition |
| --- | --- |
| Provenance | The audit records RSS/Atom inputs, selections, fetch failures, and each candidate’s score, detected Macro themes, National corroborating sources, and selection decision. |
| Recency | Every selected item has a publication time within the configured window, at most 36 hours. |
| Selection | No routine auction, stock-tip, dividend, draft-IPO/listing or IPO-tracker, market-mover, thin market-calendar, standalone currency or index recap, recycled long-range forecast, speculative meeting preview, reported ministerial discussion without a decision, investor punditry, generic placement announcement, offshore capex without an India operating effect, macro ministerial or executive-commentary, gadget-review, unrelated global-tech or offshore hypothetical-India item, generic fund-raise, startup-support, conference-preview, or workforce-gap report, ministerial or executive commentary, unsupported spokesperson claim, generic local-national, or party-political-churn item reaches the page. Macro cards use word-aware themes—not partial-word matches—do not repeat a broad theme, and leave a weak slot empty. National cards rank independent corroboration higher, may include up to three distinct events, and collapse one event to one card. A single event must not fill multiple cards. |
| Analysis | Each card has a complete-sentence brief and a distinct two-sentence `Why it matters`: mechanism first, next signal or tradeoff second. |
| Structure | The clearly labelled Market Tape leads; Macro precedes National & Strategy, which precedes India Tech; the visible edition date is current; one catalyst module closes the issue. A daily chart is omitted unless it offers a distinct comparison or analysis. |
| Readability | The page has source links, responsive styling, focus styling, no duplicate stories, and no source-placeholder copy. |

Warnings call for a judgment check. Failures require a repair before delivery. If a feed is unavailable, record the failure in the audit and publish fewer stories instead of substituting web-search results.
